# 管理指南

Hands 是面向需要受控交付二进制文件的应用的发布和更新分发控制台。你可以在管理控制台创建应用、上传构建、分阶段发布版本、管理分享链接和反馈工单，并为团队成员或自动化任务授予所需权限。

## 登录

打开 Hands 网站，使用 Raft 登录。登录后，Hands 会打开你的第一个应用；如果尚无应用，则打开创建向导。左侧导航可以切换应用、组织和账号菜单（设置、退出登录）。

如果能够登录但看不到预期的应用，请组织管理员授予应用访问权限，或使应用对你的 Raft 服务器可见。

## 应用

每个应用都有自己的侧边栏。顶部的应用切换器可以跳转到其他应用、创建应用或返回完整列表。

- 概览：当前应用元数据和近期操作。
- 渠道：发布轨道（`main`、`preview`、`nightly`、`debug`）。
- 版本：已发布和草稿版本、分阶段发布控制。
- 构建：已上传的构建文件和元数据。
- 分享：所有公开分享链接及统计、续期、撤销和密码。
- 反馈：应用提交的工单及负责人、状态和评论。
- 访问权限：直接应用成员、部署令牌和 Raft 服务器可见性。
- 审计：近期应用活动。
- 设置：应用名称与描述、图标、客户端密钥、默认渠道、Raft 通知、公开版本历史开关和归档。已归档应用可以**永久清除**：永久删除应用及其构建、版本、工单和所有存储文件；需输入 slug 确认，接口为 `POST /api/apps/:id/purge`。

每个产品分发目标应创建一个独立的 Hands 应用。例如 Android 应用应拥有自己的 Hands 应用及发布渠道。

要连接你已加入的另一个 Raft 服务器，在组织切换菜单中选择**添加 Raft 服务器**，然后在 Raft 选择服务器并授权 Hands。完成后会切换到该服务器对应的组织；此操作不会创建 Raft 服务器或授予成员资格。同一 Raft 身份之前连接过的组织仍可在菜单中切换。

### Raft 通知 {#raft-notifications}

应用管理员可以打开**设置 → Raft 通知**，让 Hands 以应用的 Raft App Bot 身份发送所选 Webhook 事件。服务器所有者或管理员须先在 Raft 中为 Hands 应用授予机器人权限。点击**连接应用机器人**，然后在 Raft 中将机器人加入每个目标频道。输入 `#proj-mobile-release` 等频道目标，选择该频道应接收的事件，再点击**测试**。一个应用可以配置多个频道目标，各自订阅不同事件；每个目标都可以单独启用、停用、测试或移除。

**使用状态卡片**会让目标频道接收 App Store 版本、外部 TestFlight 构建、Google Play 发布以及 AppGallery 市场包和邀请测试的状态卡片。同一对象后续变化会更新原卡片，并另发一条频道消息，无需关注线程也能看到变化。已经使用文本的对象保留原历史；开启后首次出现的新对象才开始使用卡片。已有文本线程的 AppGallery 构建继续使用文本。如果对象退回文本，即使再次开启卡片也会继续使用文本。其他事件仍使用文本。超过 Raft 更新窗口的旧卡片会替换为新消息；较旧的 Raft 客户端会显示随附文本。

如果目标无法接收首张卡片，Hands 会使用文本。即使卡片请求结果尚未确认，也可以切回文本；未决请求会保留，仍可能完成。如果在请求核对完成之前收到后续事件，Hands 会发送带警告的文本，提示旧卡片可能过时。当重试确认较早的更新后，如果卡片仍启用且处于更新窗口内，Hands 也会尝试将卡片更新到时间顺序明确的最新状态。在此之前，或事件无法排序时，请以频道中较新的消息为准。投递重试次数耗尽后，需要管理员使用下方的重试入口。对于首条消息结果未确定的情况，Hands 会使用原发送键尝试文本，使卡片和文本只能有一个成功。首条消息尚未确定时，后续事件可能延迟。

目标最多显示 25 条失败的发布状态通知。**重试**会使用所选事件的原始内容和幂等键安排重新投递，不会丢弃结果未确定的卡片请求。重试记入应用审计历史。重新开启卡片前，请先解决所有未决请求。事件没有可靠发生时间，或与另一变更时间相同时，Hands 会发送文本，不会猜测顺序。

新反馈和缺陷报告通知会包含用户消息的短摘要。请选择允许成员阅读这些反馈的频道；摘要可能包含用户提交的信息。HTTP(S) URL 会被移除，摘要中的 Raft 提及不会触发。通知不包含崩溃文本、附件或评论正文。反馈通知包含 `hands feedback show <app> <ticket>` 命令；查看完整工单仍需 Hands 权限。`feedback:comment_created` 和 `feedback:status_changed` 事件针对报告人拥有的工单发送。同一工单发往同一目标的更新会发布在已有 Raft 线程中。

TestFlight 通知可能包含测试组名称和开发者测试说明的短摘要，请选择允许成员查看这些信息的频道。摘要中的 HTTP(S) URL 和 Raft 提及会被中和。Play 状态通知会区分首次观察快照和后续状态转换。

Hands 为每个 Raft 服务器安装保存一份加密机器人凭据，控制台不会显示该凭据。在同一服务器连接另一个 Hands 应用时，会复用该安装的凭据，而不是轮换。现有 Webhook 生产者使用相同的投递队列和重试策略。文本模式下，每次发布、构建和商店状态事件都会作为频道消息出现，无需关注线程即可看到后续变化；同一工单的反馈更新仍留在它的线程中。状态卡片的原地更新本身是静默的；Hands 会另发频道消息。消息不包含服务商凭据、崩溃附件或不可信的服务商原文。Apple 审核拒绝通知包含版本、状态、时间和 App Store Connect 链接；拒绝正文仍需在 App Store Connect 中查看。

## 版本

标准流程遵循先草稿的规则：CI 使用生成的更新说明创建**草稿**，用户或智能体审核、编写最终更新说明（可选双语），然后明确发布。参见仓库文档中的发布手册。

1. CI 或 `hands builds publish-android --draft` 创建草稿。
2. 在版本页面或使用 `hands releases show` 审核。
3. 编写最终更新说明；支持按语言提供（`hands releases update … --changelog-file zh=zh.md --changelog-file en=en.md`），客户端收到与系统语言区域匹配的内容。
4. 从版本行或使用 `hands releases publish` 发布。

对于 Android，Hands 根据 `version_code` 选择更新。仅当已发布版本的 `version_code` 高于客户端报告的值时，设备才会收到更新。

草稿、活动或已被替代的版本会占用其应用、渠道、产品类型、发布类型和版本号的组合。取消会停用该生命周期并释放组合供修正后的上传使用，同时保留旧版本 ID、构建、文件和审计历史。只有在替代版本占用该版本号之前才能恢复已取消版本；之后应操作替代版本。对于已分发的 Android 构建，请使用更高的版本号，以便已安装的客户端收到修正。

### 分阶段发布

创建或编辑全量版本时设置发布百分比（数字输入框提供 5/25/50/100 预设），并可通过**提高发布比例**逐步增加。在同一版本上选择任意数量的**始终包含的设备组**，用于验收或质量检查。组内成员不受分桶限制，始终收到目标版本；其他设备在百分比提高时保留稳定分桶。被比例限制排除的设备及匿名客户端会收到上一个符合条件的全量版本，直到发布达到 100%。

每个版本行显示按安装去重的设备数（UV）：已经**使用此版本**并进行检查的设备数，以及被**提供**该版本的旧设备数。将鼠标悬停在数字上可查看累计更新检查事件数（PV）。收集 UV 需要稳定的设备 ID，且从指标升级后开始；历史 PV 汇总不能转换成精确的历史 UV。

应用概览还通过 `GET /api/apps/:id/analytics/versions` 显示按版本统计：所选窗口内报告过的设备、已见设备总数、更新检查的当前和已提供数量、反馈及崩溃数量，以及每个版本和渠道的文件下载次数。数据来自受限流的 SDK 指标请求、更新检查、反馈工单和构建文件下载计数器。这些指标显示活跃或近期设备，并非不受限流影响的实时在线心跳。

## 构建

构建保存上传的文件和来源信息。Hands 区分可安装文件与辅助文件：

| 文件类型 | 用途 |
|---|---|
| `installable` | 客户端可安装或下载的 APK 或其他版本文件。 |
| `proguard-mapping` | 用于崩溃符号化的 Android R8/ProGuard 映射文件。 |
| `native-symbols` | 原生调试符号。 |
| `metadata-file` | 与构建一起存档的 CI 或构建元数据。 |
| `app-icon` | 从上传 APK 自动提取的启动图标。 |

注册可安装 APK 会触发自动解析：服务端使用 aapt 提取包 ID、SDK 级别和启动图标，无需额外 CI 参数。公开更新检查只返回可安装文件；已认证的管理员和发布者仍可访问辅助文件。

## 渠道

渠道用于区分 `main`、`preview`、`nightly` 或 `debug` 等发布轨道。先将测试构建发布到非生产渠道，验证后再发布到生产渠道。

Android 客户端应发送自身配置使用的渠道。调试构建可以指向 `debug`，正式构建通常指向 `main`。

## 分享

分享页面列出应用的所有公开分享链接，包括版本、创建者、有效期、状态、密码标记及查看和下载统计。你可以创建链接并选择性设置密码、延长 7 天、为已有链接设置或移除密码，以及撤销链接。分享 URL 仅在创建时显示一次；令牌以哈希形式存储。

分享页面显示版本的真实应用图标、桌面端二维码、本地化更新说明和实时统计。受密码保护的页面会先要求输入密码，再显示下载内容。

```bash
hands releases share raft-android <release-id> --password <pw>   # 密码可选
hands releases update-share raft-android <release-id> <share-id> --ttl-seconds 1209600
hands releases revoke-share raft-android <release-id> <share-id>
```

分享页面适合人工审核和手动测试。应用内更新检查应使用公开更新 API。

## 反馈

反馈页面是接收应用报告的轻量工单系统；报告可通过 SDK 的 `HandsFeedback` 或公开反馈接口提交。每张工单包含消息、联系方式、应用版本、设备信息（包括分阶段发布设备 ID）及最多九个附件。

- 工单是可分享的页面（`/apps/<id>/feedback/<ticket>`）。
- 可以使用状态（`open → in_progress → resolved/closed`）、负责人（分配给我、编辑或移除负责人）和评论记录处理工单。
- 提交时会向组织 Webhook 订阅者发送 `feedback:new`。
- 崩溃告警：首次为应用观察到某个崩溃签名时发送 `crash:new_group`；一小时内同一签名达到 10、50 和 100 次时发送 `crash:spike`。在组织设置 → Webhook 中订阅任一事件，即可接收告警而不必轮询控制台。

崩溃工单（`kind=crash`，由 SDK 崩溃报告器自动提交）有一个用于分组的**签名**（异常类加应用顶部堆栈帧）。**崩溃分组**视图按签名汇总发生次数和设备数量。如果为该版本上传了构建的 ProGuard/R8 `mapping.txt`，并将其作为 `proguard-mapping` 文件，Hands 会在容器中自动反混淆堆栈，将还原结果作为工单评论发布。

## 版本历史

设置 → **公开版本历史**会开放 `/apps/<slug>/history`：公开页面列出已发布版本、本地化更新说明和每个版本的下载链接。该功能默认关闭；关闭时页面返回 404。

## 访问权限

访问权限页面控制谁可以查看或发布应用。

| 访问类型 | 用途 |
|---|---|
| 直接应用成员 | 为某个用户或智能体授予该应用上的角色。 |
| Raft 服务器可见性 | 使另一 Raft 服务器上的账号可以看到应用。 |
| 部署令牌 | 为 CI 或智能体授予限定于该应用的 API 访问权限。 |

对于另一台已连接 Raft 服务器上的主体，请其运行 Hands 的 `whoami` Agent Login 操作，发送非秘密的 Hands 账号 ID。在**添加直接应用成员**中粘贴该 ID，而不是选择同组织主体。该账号必须至少登录过一次 Hands。Hands 会以原子方式添加缺失的组织 `viewer` 成员关系和所选应用角色。

部署令牌是限定于应用的 Bearer 令牌。应为自动化任务创建令牌，不要复用用户浏览器会话。创建时请复制令牌；Hands 只显示一次原始令牌。每个令牌记录创建者，使用它执行的操作在审计日志和发布来源中归属为 `deploy-token:<name>@<app>`。

角色包括 `viewer`（读取）、`member`（协作，例如处理反馈）、`publisher`（发布构建和版本）和 `admin`（配置、管理成员、持有秘密）。完整角色模型及接口与角色的对应关系见[权限参考](permissions.md)。

## 常见问题

### 找不到更新

检查已发布版本是否与客户端处于同一渠道、`version_code` 是否更高、是否包含兼容的可安装文件。对于部分发布的版本，还应检查设备分桶是否落在发布百分比内。

### 下载链接已过期

公开文件 URL 带签名且有时效。刷新分享页面或重新执行更新检查，即可获取新的 URL。

### 403 禁止访问

你的账号或部署令牌缺少执行该操作所需的角色。响应可供机器读取，智能体或命令行可以据此指出修复方式：

```json
{
  "error": "insufficient_org_role",       // 或 "insufficient_app_role"
  "required_role": "member",
  "current_role": "viewer",
  "resource": "POST /api/apps",            // 尝试执行的操作
  "org_id": "…", "app_id": null,
  "manage_url": "https://app.hands.build/orgs/{orgId}/members"
}
```

解决时，组织 **admin/owner** 打开 `manage_url`，在**组织 → 成员**中调整组织角色，或在应用的**访问权限**页中调整应用角色，将账号提升到 `required_role`，然后重试相同请求。

注意：创建应用（`POST /api/apps`）需要**组织 member 或更高角色**；应用级成员角色或部署令牌不够。新通过 Agent Login 登录的智能体通常从 **member** 开始；组织管理员可以手动分配只读的 **viewer** 角色。

## 无需服务账号密钥连接 Google Play

完整设置及故障排查步骤见 [Google Play 授权设置指南](google-play-oauth.md)。

打开 Android 应用设置并找到 Google Play。输入包名以及内部测试、封闭测试和正式发布轨道名称，然后选择**使用 Google 授权**。登录有权访问该包和这些轨道的 Google Play Console 账号。只有 Hands 应用管理员中的用户可以授权。连接测试会检查访问权限，不会发布版本。

Hands 在服务端加密授权，并在需要时刷新访问权限。如果 Google 按钮不可用，Hands 运营人员必须先配置 Google OAuth 客户端和私有 Play 适配器。现有服务账号 JSON 连接仍受支持。

**解除绑定**会移除 Hands 为该应用存储的授权。要同时撤销 Google 授权，请打开 Google 账号连接并移除 Hands；这可能影响使用同一 Google 账号的其他应用。Play 发布仍需要有效签名的 AAB 以及现有验收和审批步骤。
