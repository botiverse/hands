# 设计供智能体使用的状态接口

Hands 面向智能体设计：智能体应当能够轮询变化并自行处理，无需人在中间参与。这改变了 API 必须提供的保证。

人可以按“最近更新”排序、浏览列表并跳过熟悉的内容。近似结果也能接受，因为人会继续筛选。智能体不能这样做：它询问“上次查看后发生了什么变化”，然后根据答案行动，因此**漏掉一行就会漏掉一次操作，多出一行就可能重复操作**。

本文说明 Hands 自身变更流采用的模式，也适用于需要镜像 Hands 状态的集成，或自行设计供智能体读取的数据流。

## 1. 提供精确游标，而非时间戳

智能体需要可从中恢复的全序，即“序号 N 之后的所有内容”。

`updated_at` 时间戳看似足够，实际上并不够：

- **同一毫秒内发生冲突。** 同一条记录在一毫秒内变化两次时无法区分，`updated_at > T` 会悄悄漏掉其中一次。
- **任何修改都会推进时间戳。** 触及记录的任何写入都会更新它，包括消费者不关心的内部处理。

应使用数据库分配的单调递增序号，并作为不透明游标暴露。消费者保存最后看到的值，再从该值之后请求下一页。

如果平台已有序号机制，请复用它，而不是自行实现单调性：正确处理并发分配、序号间隔和不可变性比看起来复杂。

**决定序号存放位置前，先测量写入成本。** 由触发器分配序号通常会将一次插入变成插入加更新；每个包含序号列的索引在序号推进时也要删除并重新插入。值得直接比较两种载体：

| 载体 | 成本 | 权衡 |
|---|---|---|
| 现有记录上的列 | 同一操作已经更新该记录时成本较低 | 热点记录的索引维护略多 |
| 只追加的独立表 | 不更新热点记录 | 多写一行、读取时需要联表，且无限增长需要保留策略 |

游标索引应先按作用范围排序，例如 `(tenant, sequence)`，而不是 `(sequence)`；否则扫描会跨过其他租户的记录，之后才将其过滤。

## 2. 仅在发生实质变更时推进

明确记录哪些事件会推进序号，将内部机制排除在外。

| 实质变更 | 非实质变更 |
|---|---|
| 创建记录 | 后台后处理 |
| 消费者需要报告的字段发生变化 | 将字段写成当前值的无操作写入 |
| 用户添加评论 | 消费者自己的已读回执 |

如果维护操作推进游标，智能体就会被系统自身的噪声反复唤醒，并重复报告未变化的项目；游标正是为避免这种故障而设计的。

**内容未变化时必须产生零增量。** 应用测试保证这一点，而不只是写注释，因为之后很容易在不知情的情况下破坏它。

## 3. 不要在真实状态中存储消费者进度

以下两种看似方便的做法实际上不可取：

- **“需要处理”标记。** 它记录的是某个特定消费者是否已处理，将消费者状态放进了你的数据。一旦出现第二个消费者就会失效。
- **字段级变更历史。** 用它告知消费者哪些字段改变；但消费者已经持有之前的快照，可以在本地比较得到同样结果。存储历史会增加一份必须保持一致的真实状态，却没有提供新信息。

返回游标之后对象的**当前快照**。消费者知道自己处理到哪里；你的系统只需知道现在的真实状态。

## 4. 所有对外可见的载体都不得包含仅供内部使用的值

如果序号会因仅供内部使用的事件（例如私有备注、内部处理）推进，那么**序号本身也是内部数据**，即使它不包含文本。

这一点容易遗漏，因为权限检查通常针对内容。隐藏内部评论正文的过滤器不会隐藏计数器，后者是元数据而不是内容。但外部读取者观察数值变化，就能获知某条记录**何时以及多频繁地发生内部活动**。虽然正文没有泄露，活动的存在和频率却泄露了。

因此规则适用于所有载体，而不只是字段。内部序号、**两个序号之间的差值**及由其派生的任何计数都不能出现在：

- 列表和详情响应中；
- 事件载荷和 Webhook 中；
- **分页游标中**。

最后一项最容易遗漏。任何持有者都能读取以 Base64 编码的 JSON 游标：编码不能隐藏内容，仅签名也只保证完整性而不保密。如果游标必须携带内部值，应对其加密并认证，或使用随机令牌在服务端查找；否则，应从可以安全公开的值派生游标。

审查权限时应推广这一原则：计数器、ETag、`updated_at`、结果总数和分页游标都可能暴露字段级删减本来要防止的推断信息。

## 5. 按租户限定序号范围

优先为每个应用或租户维护独立序号，而不是使用全局序号。

功能上两者等价，因为查询都会按租户过滤。差别出现在故障时：泄漏的全局计数器会让读取者推知**所有**租户的活动量；泄漏的租户级计数器只反映该租户自身。

代价是每个租户一条状态记录而不是全局一条；分配逻辑不变，索引也已经以租户开头。

## 检查清单

对于任何供智能体使用的数据流：

- [ ] 由数据库分配单调序号，而不是使用时间戳。
- [ ] 写明实质变更的定义，并测试输入不变时产生零增量。
- [ ] 测量写入成本，并据此选择载体。
- [ ] 游标索引以查询作用范围开头。
- [ ] 返回快照；不存储消费者进度或消费者可以自行推导的数据。
- [ ] 响应、事件、Webhook 和游标不包含内部值；用测试确保一旦加入就失败。
- [ ] 序号按租户限定范围。
